## Client and content

- **C1 (low-medium, confirmed): grounded dead reckoning pops other players onto blocks and down mid-fall.** `comet/src/Comet.Client/RemoteEntities.cs:345-350`. The step allowance is `max(StepReach, distance since the state)`, measured from the state, so after d metres of reckoning any ground up to d higher or lower counts as walked (45°), far above the motor's 0.35 m step. Against the real world: running at the 1 m block at (10, -4) during a hold, the entity slides into its side, then pops up 1.1 m in one frame; walking off the 1 m block it falls 0.13 s then snaps down 0.74 m; off the 2 m block, a 1.22 m snap. Unblended, since blends only start when a state arrives. Fix: accept ground within about `StepHeight` plus `GroundSnap` of the last drawn height (or march in sub-steps of at most `StepReach`); a higher rise is a wall that stops horizontal motion. Slopes (the island's steepest is 22°), the 0.3 m step and a state at a jump's apex are fine.
- **C2 (low-medium, plausible): no connect timeout.** `comet/src/Comet.Client/WebSocketTransport.cs:73` connects with `CancellationToken.None`, and `JoinClient` has no timer. A black-holed address (the public test build's DNS still pointing at a terminated instance) leaves "Joining…" up for about 2 minutes on Linux, or the browser's own timeout. Pre-existing; matters for step 4. **Goes in the reconnect PR (todo 5), not this one** (project lead). Fix: a connect timeout of a few seconds in the transport (and the browser one), failing with a reason.
- **C3 (low, confirmed): the bad-address message never reaches the player.** `shapeland/unity/Assets/Scripts/JoinClient.cs:157-160` with `JoinScreen.cs:241-250`: `OnFailed` ignores the error text, so a malformed `?server=` on the web says "Couldn't reach the game server. It may not be running right now." Fix: show the bad-address reason as such.
- **C4 (trivial, confirmed): misplaced comment.** `shapeland/src/ShapeLand.Bots/Bot.cs:289-292`: `IsCheaterName` sits between `CountOwnHitch`'s comment and the method.
- Not checked by the reviewer, but covered elsewhere: the Unity Play mode tests (37) passed on this branch, including the `TryServerUrl` and scheme cases on Mono. Still unverified: Mono's `ClientWebSocket` on Abort, an editor domain reload during a background close (up to 5 s), a frozen (not just hidden) browser tab.

## Scripts

- **T1 (low-medium, confirmed): netrun carries on after Ctrl+C.** `tools/shapeland-netrun.sh:105`: `trap cleanup EXIT INT TERM`, and `cleanup` never exits, so after Ctrl+C the script continues (e.g. `docker wait` on a removed container) with a wrong exit code. Pre-existing. Fix: `trap 'cleanup; exit 130' INT` and `trap 'cleanup; exit 143' TERM`. `shapeland-web.sh:154` has the same pattern (harmless there, the last stage).
- **T2 (very low, plausible): `unity-batch.sh` can still leave the editor running** if Ctrl+C lands between starting it (line 43) and setting the traps (57-58), or on an unexpected `set -e` exit in the loop. Fix: set the traps before starting the editor, and add an EXIT trap. Also `stop_unity` signals only the editor's pid, so helper processes can outlive a `kill -9` (they don't hold the lock).
- **T3 (low, plausible): one bad id fails the whole AWS terminate.** `tools/StackBench/aws/run.sh:51-53`: a non-id (such as `None`) in the merged list makes `terminate-instances` reject every id. Fix: keep only `^i-` ids.
- **T4 (very low, confirmed): a "Far cheater" would count as an honest far player** in netrun's summary (`tools/shapeland-netrun.sh:99`); unreachable today (far groups run with no cheaters). Fix: match `Cheater |cheater `.
- **T5 (minor):** `quietly` is defined identically in `shapeland-web.sh:106` and `shapeland-netrun.sh:79`; `aws/run.sh:30` warns about uncommitted changes in `comet/src` and `tools/StackBench` but not the newly archived `tools/docker`.

## Server fixes and client input

- **S1 (high, confirmed): chat can disconnect every player.** Server frames have no size cap (`Connection.cs:46`, 136-154; `ShapeLandGame.cs:278-285`), but clients drop frames over 64 KB (`WebSocketTransport.cs:30`, `BrowserWebSocketTransport.cs:23`). 40 joined connections each sending 3 chat lines of 200 CJK characters (about 600 bytes each) give every player one 73 KB frame (measured), and they all disconnect; the chat burst refills every 6 s. A victim whose sends stall hits it with fewer senders. Fix: split tick frames (or cap them) below the client limit, and keep the event cap consistent with it.
- **S2 (medium, confirmed by reading): no limit on connections**, so the per-connection limits can be multiplied (`CometServerExtensions.cs:267-285`, `Connection.cs:198-224`, `ShapeLandGame.cs:130`, 162-171). No cap on total or per-IP connections, no join timeout, no receive idle timeout: thousands of connections that never join (or trickle a partial frame) each hold about 20 KB indefinitely, and `registry.Add` copies the array on every connect; connect-join-disconnect cycles send a spawn and despawn to everyone and log two lines each; each unjoined connection can send 120 join attempts a second, each scanning every player for a name clash. Matters for the public test build. Fix: connection caps (total and per IP), a join timeout, an idle timeout, join attempts rate-limited.
- **S3 (medium, confirmed): facing isn't held to a range.** Any finite facing is accepted and relayed (`MovementValidator.cs:207`, 214-217; `ShapeLandGame.cs:368`, 385): `float.MaxValue` then `-float.MaxValue` makes every viewer's `RemoteEntities.LerpAngle` return NaN, and later joiners get the huge value in the spawn. Fix: wrap facing into (-π, π] on accept.
- **S4 (medium, confirmed in scratch): a report guessing the next correction sequence during a server-finished fall leaves the validator stuck falling.** `MovementValidator.cs:162-165`, 289; `Fall` at 281 and 311. `Check` relies only on the sequence (which just goes up by one) and never checks `_serverFalling`: a client sends sequence 1 with a ground position, it's accepted, the flag stays set, others are sent the frozen fall velocity while the player walks, and on the next jump `Fall` resumes the old fall and moves them 46 m up to it. Fix: while the server finishes a fall, every report is stale (or make the sequence unguessable).
- **S5 (medium, confirmed): stopping after a failed tick takes 30 s with every client frozen.** `Connection.cs:156`, 165 use only `RequestAborted`, and `ShapeLandServer.cs:163-169` doesn't close connections, so Kestrel waits its full shutdown timeout; meanwhile `_inbox` keeps filling. Normal shutdowns too. Fix: link connections to `ApplicationStopping` and close them.
- **S6 (low, confirmed in scratch): chat's filter skips characters outside the Basic Multilingual Plane** (`ShapeLandRules.cs:61-63` appends surrogate pairs unchecked): tag characters (U+E0001, U+E0041), planes 15-16 private use (U+F0000) and musical formatting (U+1D173) pass; a line of only tag characters shows as an invisible line or empty bubble; 150 stacked combining marks spill out of bubbles. Fix: check the pair's category (`char.GetUnicodeCategory(string, int)`), and cap combining marks per character.
- **S7 (low, confirmed by reading): frames with no messages cost nothing against the rate limit** (`Connection.cs:229-249`): floods of 4-byte header-only frames or 1-byte fragments are never dropped. Fix: charge frames too.
- **S8 (low, plausible): an honest client can trip the 240-message burst after a long upstream-only stall** (`Connection.cs:37-40`): about 16 messages a second, and both client transports queue unsent frames without limit, so a 15 s or longer client-to-server stall (wifi roaming) arrives at once and is dropped as a protocol error. Fix: clients drop superseded position reports while their send is stalled (latest only), or the server drops excess reports rather than the connection.
- Not checked: Unity's reaction to a NaN rotation (only up to `LerpAngle`), real memory per idle connection, real TCP stalls, the browser transport's oversized-frame handling (read only).
